# Getting started with the demo project

This small project is intended as a hands-on playground, so the first thing you do is get it running on your own machine. Clone the repository with `git clone <repo-url>`, then open a new terminal in the cloned folder and run `ls` to see what is already there. There are no build steps: everything lives in plain Markdown, so no dependencies, compilers, or configuration files need to be installed, and the whole project can even be viewed from a bare-bones text editor.

Once the directory is open, start from the top-level `README.md` to get the orientation of the project — its goals, its layout, and where the contributing guidelines live. The one thing worth doing early is creating your own branch (for example `git checkout -b feature/your-name`) before you make changes, so that you are always working from a clean copy of the code and so your work stays easy to compare, review, and merge later. Long-lived main-branch commits make it hard for reviewers to understand what actually changed.

After the first commit, commit your work with a clear message that tells another person what you did and why, open a pull request against `main` with a title and description that point at the tracker issue it fulfills, and use the review comments to discuss the change explicitly. Review is not a ritual — it is the most useful way to learn how the repository is used, to catch a mistake before it ships, and to give back exactly the kind of feedback that makes the next contribution easier to make. Treat every comment on your pull request as an invitation, not a verdict.
